# 控制策略写前备份与验证

启用本地后台后，响应/沉默、全局响应/沉默、用户封禁/解封、插件按群及全局禁止/允许，共用与开关和 AI 配置相同的私有控制库备份目录。后台关闭时不安装自动备份钩子。业务消息计数、其他数据库及外部编辑不属于本轮自动备份范围。

在共享 Manager 锁内先检查持久化状态，区分未找到与读库失败。有变化时先建立含已提交 WAL 数据的完整 SQLite 快照，再执行原单条写入；备份或写入失败保留磁盘及缓存状态，SQL 写入失败前已成功建立的快照可用于恢复。重复操作不额外备份，重复响应/沉默提示已有状态。全局响应优先规则不变，无本地行时沉默不删除全局响应；按群允许不撤销全局禁止。

禁止/允许原方法没有错误返回，聊天指令无论保存是否成功都可能报告成功。本轮改为检查 Ban/Permit 的 error 返回，封禁/解封也明确报告失败。错误回复不直接输出底层 SQL 或文件路径。批量操作按账号逐项执行和备份，允许部分成功，报告对应每一项结果；不是整个批次的原子事务。群内 @ 与原权限规则保留。

模块测试验证八类写入的旧状态快照、WAL 内容、重复操作、重新打开数据库后的持久化、备份失败、SQL 触发器故障及读取失败；并验证全局回退规则和八个并发重复封禁只产生一个快照。后台、基础指令及 LLM 回归通过，相关 Go 静态检查和 Windows CGO=0 构建通过。
