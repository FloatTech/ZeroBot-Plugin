# 回复快照离线核对

维护者从仓库运行`node scripts/check-reply-evidence.mjs --before 起始回复快照.json --after 结束回复快照.json --output 尚不存在的结果.json`，自动核对已下载的[回复统计快照](qq-reply-snapshot.md)。需要Node.js和资料读取权限，不需要后台密码或浏览器连接；读取后立即生效，无需构建或重启机器人。

两份文件必须来自同一次统计起点，读取时间递增，累计次数和首末最长值不能倒退。工具验证固定三类、计数守恒、平均分母、UTC纳秒时间及可读取的进程字段；按固定字段复制输出，附加的聊天、账号、密钥、路径等内容不会复制。窗口新任务和结束任务允许不同，起点进行中的任务可以在窗口内结束；窗口内新增确认回执也不保证对应窗口内新发起任务。

`window.durationNanoseconds`保留精确间隔的十进制字符串，`durationSeconds`用于显示。`snapshotProcessMatches`表示两份快照都提供了相同的固定进程字段；没有资源资料时`sameProcessVerified=false`、`compatible=false`和`temporalCoverage=unavailable`保持，不把文件内部身份一致冒充资源关联。`replyObservationPassed`对应当前输入模式的观察条件，业务验收始终另列为false。

输出保留两份累计快照及窗口任务、发送回执的次数变化，不计算窗口平均/最长耗时，不把累计最长值相减。部分回复后失败的任务仍按原失败和有回复分母记录；零长度窗口仅用于诊断，不能算有效观察。统计起点或前后进程字段改变拒绝合并；缺少进程字段时仅核对数字与时间，明确标记关联未证明。

可附加`--resource .local/live-observation/本次目录`同时核对已完成的资源观察。工具复用资源重算检查，判断回复读取窗口是否完整位于资源首末样本内，核对PID、操作系统创建时间和程序摘要；资料有效、资源检查通过、时间覆盖、进程关联分别给出结果。短资源窗口、时钟漂移、不同进程或时间不重合不能判为资料兼容。不自动补齐缺少的业务证据。

退出0表示回复窗口可用于观察；附加资源时还要求完整资源检查、时间覆盖和精确进程关联均通过。退出2表示资料内部有效但观察条件不足，如零长度、缺少身份、短资源窗口或配对不兼容；退出1表示输入/配对关系无效、原始样本或摘要损坏、参数/文件/输出失败。`businessAcceptancePassed=false`始终保留，数字增长、发送确认和资料兼容都不证明QQ客户端收到、已读或真实持续业务验收完成。

每份快照JSON限制1MiB，原资源文件沿用[资源核对工具](observation-evidence-check.md)的大小和样本限制。输出文件必须尚不存在，省略`--output`仅打印结果；不会覆盖输入或已有输出。工具不读取原始日志正文、不访问网络、不采样或控制服务、不发送QQ消息或调用模型。摘要用于识别本次读取的资料，不是来源签名。
