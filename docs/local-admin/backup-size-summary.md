# 备份内容大小摘要

登录本机后台，进入“备份恢复”。成功读取列表后，筛选区域下方显示“备份内容大小”：

- 已加载记录：当前读取列表全部记录的份数、可核对内容大小、大小无法核对的份数。
- 当前匹配记录：按关键词、范围与校验状态筛选后的全部结果，跨全部分页；显示同样的份数与内容大小。
- 范围明细：启动配置、控制数据库、后台启用与地址、异常/未知范围各自的已加载和匹配摘要。

仅汇总可预览记录中非负整数的大小。损坏、不可恢复或大小字段无效的记录计入份数和“大小无法核对”，不作为零大小相加。明确的0字节是可核对大小。总和按精确字节计算；较大值附KiB/MiB等换算，两位小数四舍五入，括号内为精确字节数。

这里的大小来自最近读取的目录元数据：启动配置/后台选项统计JSON中的配置正文，控制库统计备份的SQLite文件。它不含JSON封装、manifest、目录或磁盘簇开销，不是磁盘实际占用。一次仍最多加载最近200份；存在更早未加载记录时会提示摘要不含这些记录，不能据此推断整个备份目录的总大小或可释放空间。

改变筛选立即更新匹配及范围摘要，翻页、每页份数与排序不改变总和。刷新成功后按新目录重算；读取失败保留上次摘要并注明“刷新失败”，显示最近成功读取时间。切换页面保留最近目录，返回页面按原流程刷新；退出或会话过期清空，迟到结果不能覆盖新会话。

摘要只读，不额外请求接口、读取备份正文或导出秘密，不创建/恢复/清理备份，也不改变已打开的恢复/清理预览和确认。下载清单仍沿用原固定元数据格式，摘要不加入下载文件。

验收：刷新列表，核对全部及匹配份数；组合范围/状态/关键词，观察匹配大小更新；翻页或更换排序应保持总和。无需恢复或清理日常备份。实际页面体验待验收。

自动化验证：新增4项离线Chrome场景与原152项界面共156项全部通过；64项深浅主题/窄屏布局及截图、相关Go模块/静态检查和Windows构建通过。合成200份验证全量/匹配/固定范围总和、0字节和无法核对大小、超过安全整数的精确总和及换算；排序分页不改大小、失败/刷新/预览确认保持、退出与迟到请求保护通过。未恢复或清理日常备份，实际页面体验待用户验收。

备份列表可按本地开始/结束日期组合筛选，结束日期包含完整当天；列表、大小摘要与清单采用同一组已应用日期，清理策略和恢复目标保持，见 [备份日期筛选](backup-date-filter.md)。
