# 备份列表排序

登录本机后台，进入“备份恢复”，在筛选区域的“排序”下拉框选择：

- 默认顺序：保留服务端返回的顺序，按备份编号从新到旧。
- 时间从旧到新：按备份记录的创建时间排列。
- 大小从大到小、大小从小到大：按记录的字节数排列，显示的 KiB 向上取整不影响排序。

排序先覆盖全部已加载的匹配结果，再分页；相同时间或大小保持默认顺序。不可恢复的记录，以及缺少有效排序字段的记录，放在自定义排序的最后。不根据未知数据推断时间或大小，排序不使损坏备份变得可恢复。

改变排序回到第一页。搜索、范围、校验状态与每页份数可组合使用；“清除筛选”保留排序，选择“默认顺序”恢复原顺序。刷新及切换后台页面保留排序；列表缩小后页码校正到有效页。退出、会话过期或浏览器重载恢复默认顺序。排序只保存在当前页面内存。

“下载备份清单”导出按当前排序排列的全部匹配结果，跨全部已加载页，并在 `filters.sort` 中记录 `default`、`oldest`、`largest` 或 `smallest`。导出仍仅含固定目录元数据；已打开的恢复/清理预览和确认目标不会因排序改变，恢复时仍按原编号、期限和服务端校验执行。

读取、预览、恢复、创建或清理请求中禁用排序。刷新失败保留上次列表与排序，页面和下载继续标明刷新失败；退出与迟到请求隔离沿用原流程。排序不发送请求、不创建/恢复/清理备份，也不读取配置正文或密钥。

一次仍最多加载最近200份备份；时间从旧到新只重排这200份，不能用它查看更早未加载记录。清理策略和预览清单不受排序影响。

验收：切换时间/大小排序，跨页核对记录顺序；组合筛选后下载清单，核对顺序与排序字段；打开预览后切换排序，确认备份编号与勾选保持。无需执行恢复或清理日常备份。实际页面体验待验收。

自动化验证：新增5项离线Chrome场景与原147项界面共152项全部通过；64项深浅主题/窄屏布局与截图、相关Go模块/静态检查和Windows构建通过。合成200份备份验证全量排序、稳定同值、精确字节与异常置后；真实Blob下载验证全部匹配顺序和固定sort字段；预览/清理目标保持、刷新失败/忙时/会话隔离已覆盖。未恢复或清理日常备份，实际页面体验待用户验收。

备份列表可按本地开始/结束日期组合筛选，结束日期包含完整当天；列表、大小摘要与清单采用同一组已应用日期，清理策略和恢复目标保持，见 [备份日期筛选](backup-date-filter.md)。
