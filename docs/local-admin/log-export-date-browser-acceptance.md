# 日志文件与日期范围自动验收

## 日常使用

使用后台密码登录，进入“运行日志”。填写级别、关键词和本地开始/结束时间后点击“应用筛选”；暂停时再点击“读取一次”查看当前条件。日期可只填一端，开始不能晚于结束；倒置范围会提示错误，已应用条件和已有记录保持。

点击“导出筛选日志”下载服务仍保留的匹配记录。未点击应用的级别、关键词或时间输入不影响导出；清空当前显示也不删除服务保留记录。空匹配仍下载有范围说明的文本。格式和保留限制见[日志导出](log-export-2026-10-02.md)、[日期筛选](log-time-filter.md)和[清空显示](log-clear-display.md)。

原生日期控件会把零秒规范化为分钟格式，例如`2026-10-12T19:26`；非零秒可显示为`2026-10-12T19:26:56`。自动填写时使用控件的规范化格式，操作后读取实际值确认，再应用。之前带零秒的填写动作曾被工具报告失败而实际值已变为分钟格式，本轮分钟及非零秒输入均正常，没有修改产品的日期解析规则。

## 自动核验方法

使用[独立后台](isolated-admin-acceptance.md)产生的本次URL和随机测试密码，由已授权Chrome执行真实按钮和表单操作。日志仅来自独立程序及模拟OneBot，不向真实QQ或模型发送请求。暂停后记录页面的日志ID、时间、级别与正文，用于比较实际下载文件。

本轮官方浏览器下载等待未返回路径，改为在UI发起下载后，只读定位Windows已知下载目录中的本次输出文件。系统提供目录，本次为`<项目目录>`；先记录匹配`zerobot-logs-<UTC时间>.txt`的已有文件名，再执行一次导出，等待唯一新增完整`.txt`文件。比较下载时段、文件名、字节数、SHA-256、范围说明及记录内容，把证据副本保留到忽略的本次验收目录，下载原件保留。此过程是对已下载文件的核验，不读取浏览器配置、密码、会话或下载历史。

下载事件等待超时只说明该观察接口没有返回，不能仅凭它认定下载失败；页面“已发起下载”或HTTP200也不能单独代替文件证明。必须取得实际文件再确认内容。本轮没有更改下载权限、下载设置或程序导出实现。
