# Windows服务路径与目录联接

同一项目可能通过目录联接使用多个路径入口。启停脚本先解析实际项目根，再核对服务脚本、工作目录、可执行文件、PID及进程启动时间；不能只凭文件名或程序摘要判断进程归属。

启动会复用属于同一实际项目的托管任务，避免通过不同别名重复启动。停止仅处理身份明确匹配的本项目服务，其他目录的机器人仍是独立实例。路径显示不同本身不构成复制配置、删除联接或重置凭据的理由。

## 开发者验证

在仓库根目录执行scripts/test-service-paths.ps1。脚本在.local自建测试目录联接，检查8项任务夹具、4项进程夹具和5份脚本语法，结束时只删除已核实的测试联接，不递归操作其目标，也不启停真实服务。无需依赖开发者本机固定的C/D目录布局。

相关使用入口见[运行维护](operations.md)。运行记录中的动态路径属于本机资料，不随源码上传。
