# AI回复处理耗时

登录本机管理后台，在“运行概览”的“AI回复处理耗时”查看本次启动的GPT/群总结、普通聊天、Agent/识图任务数量与首条/最后一条回复耗时。沿用概览自动读取与刷新按钮；等待刷新时保留上次成功读取的值，切页、隐藏、退出或读取失败会清除旧显示，重新读取后更新。无需额外QQ指令，修改程序后仅重启ZeroBot生效；不改变原触发、权限、限速、内容或语音回退规则。

计时从消息进入ZeroBot匹配流程开始，到当前群或私聊的实际回复发送调用返回。包含匹配流程中此前经过的检查、引用/历史读取、模型处理和发送等待；不含QQ客户端到接入程序、事件解析或框架队列之前的时间，也不证明用户收到或已读。没有匹配流程起点时从AI处理器入口计时，并单独增加“缺少匹配起点”计数，不能将它冒充完整起点。

仅实际进入AI处理的群或私聊计为任务。未触发、插件关闭、配置过滤、不符合权限、GPT空问题或限速拒绝不计；GPT与群总结归为一类，Agent图片描述和回退普通聊天仍归本次Agent任务，不重复计数。非AI插件、频道、单独“发送AI语音”命令暂不在本项范围。

结束任务分为：

- **取得回复回执**：至少一条当前会话回复取得确认，且本任务没有记录处理或发送失败。
- **失败**：模型/历史/记录处理失败，或某次当前会话发送回执未确认；即使其他回复成功，也保持失败。
- **没有回复**：没有确认回复，也没有记录失败，例如模型输出为空或Agent只执行查询动作。
- **进行中**：处理尚未返回，不计入已结束任务的平均耗时。

首条/最后一条耗时的平均和最长值只统计“已经结束且至少有一条确认回复”的任务；包含部分回复后失败的任务，不能据这些平均数推断成功率。最后一条指任务内最后一条确认回复，不是处理器退出时刻。多段文本、合并转发及普通聊天的群AI语音按原方式发送，不额外发送测试消息；“少女思考中”、限速和错误提示不算实质AI回复。

普通文本/合并转发要求接口`status=ok`、`retcode=0`及可解析的非零消息编号；负整数编号仍可用。QQ原生群AI语音成功时可能返回0编号，沿用已验收的`status=ok`和`retcode=0`确认口径。仅记录当前会话的发送，Agent向其他目标发送不算当前提问的回复；非发送动作不计回执。没有确认不代表一定没发出，统计不会自动重试。

统计只保留固定三类累计数字和时间，不保存账号、群号、消息编号、正文、模型地址、密钥、逐条历史或请求参数。重启清零，没有清零接口或持久化记录。认证概览中的`replyTasks`提供同口径固定字段及可读取的进程信息；现有模型观察报告仍只包含模型传输统计，不自动加入本项。真实持续负载与QQ客户端端到端体验仍须另行验收。

实际Chrome独立实例`run-3438327210`使用150毫秒本地模型延迟，3次模拟GPT均完成并取得确认，进行中/失败/无回复/缺起点均为0；平均首条及最后一条193.787毫秒、最长206.510毫秒，模型传输平均151.326毫秒，页面分别显示0.194/0.207秒，与源数据舍入一致。初次发送完成通知后即时快照仍有1项进行中，待发送回执和处理器结束再读后3项全部结束，未将即时状态误判为失败。12个Chrome核对标记及8种320/375/640/1280px×深浅布局通过，桌面/小屏截图已检查；切页清除及返回读取、重启清零和原测试密码通过。两次启动、1批3次模拟请求、正常停止与凭据保持正确，自建页已关闭，主题/视口已恢复。程序启动器不代替Chrome验收，其`browserAcceptancePassed=false`与独立页面证据区分。

维护者可运行`go run scripts/start-model-observation-acceptance.go -binary-name zerobot.exe -model-delay 150ms -lifetime 20m`建立独立实例。`-model-delay`只延迟本地合成模型，允许0～2秒、默认0，不修改日常模型或QQ连接。`requests`发送一批3次模拟GPT，待任务结束后`status`保存模型与回复统计；`restart`检查新起点及零值，`stop`关闭实例。随机测试密码仅在该目录`login.txt`；不可使用此模拟实例证明真实QQ延迟。
