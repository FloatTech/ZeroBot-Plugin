# 插件管理与 SQLite 写前快照

## 行为与数据来源

页面使用实际编译注册的 108 个插件及同一个 `data/control/plugins.db`。查看全局或手工填写一个正整数群号；API 群号以字符串传递，避免 JavaScript 大整数精度问题。只接受注册插件，拒绝负群号、非法模式、缺失版本、未登录或无有效 CSRF 的写请求。

最终规则为：显式全局覆盖 → 此群显式设置 → 当前默认值。全局覆盖也作用于私聊；群设置不会泄漏到其他群或私聊。卡片分别展示最终状态、来源、默认值及此范围保存的选择；存在全局覆盖时会说明群选择暂不决定生效结果。

保存后立即更新运行规则并持久化；网页和既有聊天开关/还原指令进入同一控制写入口。恢复继承会保留插件原有 62 位群参数及默认翻转标志，不删整个数据行。旧行没有继承标记时仍按原有显式状态读取。新增 `__switch_inherit` 表记录显式继承，无需迁移所有旧数据。

网页不构造聊天事件或发送 QQ 通知；需要聊天上下文的 OnEnable/OnDisable 回复回调仍由聊天指令触发。插件开关不是进程启停，也不能替代群沉默、黑名单及用户封禁规则。

前端支持搜索与查看用法；自动刷新保留未保存选择，手工刷新状态或切换范围会放弃未保存选择。旧读版本提交返回 409，写入/备份失败返回 500 并保留原开关，不提示成功。异常提示不返回数据库路径或注入的底层错误。

## 控制补丁与备份

本地复制锁定版本 zbpctrl、sqlite、zbputils 源码，由根 go.mod replace 引入，保留许可证且不修改全局模块缓存。详见 `third_party/plugin-control-patches.md`。

- 单个 Manager 锁覆盖读取、写前快照和事务写入。运行开关缓存只在成功提交后失效，解决旧读覆盖新缓存的窗口。
- 控制写入与继承标记用一个 SQLite 事务提交；第二条语句失败时前一条也回滚。SetData 的读改写同样受锁保护，保留默认翻转标志。
- 默认翻转正确保存高位标志，提交失败不改变运行默认值；数据库重开后仍可恢复。上游原有全局缺失缓存标记不再被当作禁用。
- 后台启用时安装 BeforeSwitch，网页与聊天开关/默认翻转均先快照；后台关闭时不安装备份钩子。批量聊天命令逐插件执行，失败报告未全部完成，不声称整批原子化。

备份目录 `.local/admin/backups/<UTC 时间>-<随机标识>-control/` 包含：

| 文件 | 内容 |
| --- | --- |
| plugins.sqlite | SQLite VACUUM INTO 一致性快照，包含已提交 WAL 中的数据 |
| manifest.json | 版本 1、时间、范围 control-db、文件名和 SHA256 |

备份在当前 Windows 用户及 SYSTEM 受限目录中创建，目标空文件先设权限再让 SQLite 写入；完成后同步文件并写清单。快照语句有五秒期限。失败时开关不继续写入，不完整目录保留供诊断，没有恢复接口会读取它。无实际开关变化不重复创建备份。

快照覆盖整个控制库，可能含模型密钥等扩展配置，不公开网页下载、不进入 Git。AI 扩展、黑名单、沉默等其他写入尚未接入自动备份；聊天记录、媒体及全部插件业务数据库不在此范围。无完整备份列表、恢复、清理或跨 JSON/SQLite 的恢复事务。
