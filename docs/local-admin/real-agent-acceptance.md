# 真实 QQ Agent 验证步骤

本轮主人群实际查询、保存记忆、连续询问及单次ZeroBot重启后代号延续已通过，4个任务、6次成功动作响应与4条QQ回执匹配，用户确认。剩余非主人群主/成员/管理员Agent真人测试由用户取消，未执行、不记通过，也不自动要求继续测试；这些步骤作为以后重新提出需求时的参考。实际证据与恢复情况见[角色记录](ai-role-permissions.md)。

## 入口与前置条件

在响应开启、aichat/aichatcfg插件启用且当前群允许Agent的会话中，用QQ的实际@功能发送`@机器人 自然语言要求`。`/gpt`验证文字接口，不能作为Agent动作执行的证据。模型、人物设定和Agent开关由机器人主人管理，不为测试公开或更换密钥。

开始前记录当前程序及进程、启动配置、群级参数、发言者实际角色和档案序号；验证其他角色时临时移除发言者的机器人主人资格，并使用有期限的自动恢复。群身份来自实时消息，设置或撤销管理员后须核对缓存。群主/管理员使用Agent的admin权限表，只有配置中的机器人主人使用owner权限表。

先测试查询、当前群回复与记忆；无需执行禁言、踢人、退群或@全体来证明基本流程。每步等收到回复并核对记录后再继续，异常时保留失败现场。

## 允许动作与上下文

| 步骤 | 发送内容 | 核对 |
| --- | --- | --- |
| 查询与真实回复 | `@机器人 请实际查询本群信息，再把群名和成员人数回复到本群；不要猜测。` | 本次档案存在get_group_info请求及成功响应、当前群send_group_msg成功；群名/人数与只读平台查询一致 |
| 记忆 | `@机器人 本轮Agent测试代号是银色松鼠，请记住并只回复“已记住”。` | 事件和实际回复进入当前群的持久档案；这条回复本身不证明下轮记忆成功 |
| 连续对话 | `@机器人 刚才的Agent测试代号是什么？只回复代号。` | 真实回复为“银色松鼠”，本轮确有Agent处理，任务正确结束且无重复发送 |
| 重启后的延续 | 记录前三步后，仅重启ZeroBot，再发送上一条询问 | 程序与配置保持、进程确实更新；当前群档案重新加载并回复同一代号，NapCat保持登录 |

测试代号仅用于该轮验收，不按固定短语直接回显。不能用预存答案、模拟模型或普通聊天回退代替实际Agent结果。查询若未产生实际动作，保留为“收到文字，动作未验证”，不要标记通过。

## 角色与边界

在主人、非主人群主/管理员及普通成员身份下，分别用查询和当前群回复验证合法动作。非主人私聊的user白名单不含send_private_msg，沿用现有GPT与普通聊天行为，不把该动作拒绝记作故障。

非主人可另提出查询另一授权测试群的要求：该角色只能查询当前群，不应执行跨群动作。只读核对是否实际产生越界接口调用；模型自行拒绝只能证明本次没有执行，不能当作程序拦截分支已被触发。越群、非法编号和@全体两种格式的强制输出边界继续保留既有隔离回归证据，不为完成真实测试执行有影响的群管理动作。

## 证据与恢复

本机档案`data/aichat/history/<机器人QQ>.sqlite`记录event/request/response/end。只读核对本轮测试之后的序号、动作名、目标是否为当前群、成功状态和专用消息编号，不导出其他聊天正文。档案中的动作尝试还须结合实际成功响应与QQ历史回执判断，不能把模型输出当作平台执行成功。

最后恢复原主人、群身份和测试前参数，核对单实例、QQ在线、程序与完整配置摘要。真实模型、动作、任务和发送计数的口径不同，不要求数字机械相等。重启前后观察须分别保存，不能跨进程合并累计统计。连续真实业务负载另按[资源观察](live-performance-observation.md)和[联合核对](combined-observation.md)，本流程不重开用户已关闭的客户端体验待办。
