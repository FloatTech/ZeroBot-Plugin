# Windows 恢复重启与性能验收

## 隔离与执行

从仓库根目录在 Windows PowerShell 中执行：

```powershell
$env:CGO_ENABLED='0'
go run scripts/test-admin-system.go -mode restart
go run scripts/test-admin-system.go -mode performance
```

每次运行创建 `.local/admin-system/` 下的新目录，复制必需启动素材，创建测试数据库、启动配置及后台凭据。机器人连接本地模拟 OneBot，不读取日常启动配置或控制库，不发送真实 QQ 消息或调用模型。测试子进程隐藏启动、退出时停止，仅保留结果与日志；目录不进入 Git。启动器按测试 `options.json` 生成与 `service-host.ps1` 相同的程序参数，不计作实际 Windows 计划任务的恢复演练。

`-binary-name` 可指定 `.local/bin/` 中的待测 exe 文件名，默认为上述已部署构建。性能默认预热 60 秒、采样 300 秒；缩短参数仅用于脚本调试，结果中 `fullTiming=false` 不计作正式持续验收。

## 恢复后重启

1. 初始设置后台密码、群级开关、AI 模型名、全局插件禁止和用户封禁，保存三个范围的备份。
2. 修改主人账号、开关、AI、响应与封禁规则后重启，确认已保存主人生效，待重启状态清除，旧会话拒绝。
3. 恢复三个备份范围并重启，确认原主人、插件继承/群开关、AI 模型名及响应/封禁门控保留；后台使用恢复后的不同端口，旧端口不可访问，旧会话在新端口仍被拒绝，原密码和凭据文件摘要保留。
4. 恢复关闭后台的选项并重启，确认后台不再监听，但机器人仍能正常响应测试命令。

真实浏览器人工点击、日常 QQ 群完整联调仍另行验收；上述测试不使用日常配置进行破坏性演练。真实模型验证继续保留为 [TODO-AI-01](todo.md)。

## 持续性能口径

四组顺序测量：关闭后台、开启后台空闲、后台读接口每十秒刷新、日志每两秒带游标轮询。每组使用相同二进制、素材及合成配置，向同一模拟账号按约五秒间隔发送翻转指令。每两秒通过 Windows 原生进程 API 采集累计 CPU、Private Bytes 和 Working Set。CPU 百分比按本机 20 个逻辑 CPU 归一化，比较机器人进程所占全机容量；不测所有其他主机进程，也不测 Chrome 渲染。

登录和六类读接口先分别执行 10 次、20 次探测，随后预热；这些探测不计入资源对比窗口。轮询组继续记录相应读接口时延。结果保存各接口 p95、消息 p95、请求次数及完整资源样本，内存增长取采样期最大 Private Bytes 减首个样本，保留末尾值和 Working Set 峰值。登录不反复创建配置备份，轮询不发送真实消息。

目标沿用复用分析：管理读接口 p95 ≤ 500ms，登录 p95 ≤ 1s，Private Bytes 增长 ≤ 64MiB，相对关闭后台的 CPU 增量 ≤ 1 个百分点、消息 p95 增量 ≤ 100ms。固定窗口测量不能证明长期无泄漏或所有插件/流量下的表现；浏览器界面渲染和真实模型请求不在测量范围。

| 场景 | 消息 p95（ms） | 登录 p95（ms） | 最慢读接口 p95（ms） | CPU（全机容量 %） | Private Bytes 最大增长（MiB） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 关闭后台 | 196.54 | 不适用 | 不适用 | 0.0071 | 0.207 |
| 后台开启、空闲 | 197.20 | 81.30 | 19.20 | 0.0089 | 0.008 |
| 读接口每十秒刷新 | 193.94 | 79.83 | 19.78 | 0.0188 | 0.223 |
| 日志每两秒轮询 | 192.76 | 82.79 | 19.38 | 0.0091 | 0.730 |

最慢读接口均为实际插件列表；日志轮询组日志接口 p95 为 1.40ms。相对关闭后台，消息 p95 最大增量 0.66ms，机器人 CPU 最大增量约 0.012 个百分点，所有已定义的进程/接口测量阈值通过。时延小幅下降属本次采样波动，不据此声称后台加速机器人。完整样本保存在结果文件，终端仅输出汇总。

完整恢复页面人工操作可使用[本机隔离后台验收环境](isolated-admin-acceptance.md)，在独立目录准备三类基线备份与不同的当前值，终端只重启本次测试实例；自动环境检查不替代人工验收，不影响日常机器人。
