# Agent 连续对话与人物设定

## 行为与数据

| 项目 | 当前行为 |
| --- | --- |
| 行动轮数 | 移除单次任务最多 8 轮的循环；正常任务可继续执行，直到 `end_action`、没有动作或发生错误 |
| 重复操作 | 同一任务重复生成相同动作批次，包括 A/B/A 循环时停止；变化的 Echo 不视为进展，新消息可开始新任务 |
| 对话留存 | SQLite 持久保存已记录的事件、动作尝试、实际响应与任务结束标记，没有按轮数、条数或时间自动删除的规则 |
| 会话隔离 | 每个机器人账号独立数据库；正数会话编号为群，负数为私聊用户；群内保留发言者身份 |
| 修改人物设定 | 更新运行实例，保留历史；正在执行的旧设定任务停止，后续消息使用新设定 |
| 重启 | 下一条事件创建 Agent 时重新加载当前会话记录；升级前只在旧进程内存中的记录无法补回 |
| 手动重置 | 主人指令 `重置AI聊天Agent` 为已知会话写入重置标记，从新上下文开始；旧记录继续留在数据库 |
| 请求容量 | 官方 DeepSeek 每次加载近期历史最多约 900,000 UTF-8 字节，给系统提示、记忆与输出留空间；超出的早期内容只从本次请求省略，不删除磁盘记录 |
| 其他限制 | 单次模型 HTTP 请求仍有 30 秒超时，输出长度参数沿用原设置；取消轮数限制不等于提供方上下文和单次输出无限 |

记录位于仓库内 `data/aichat/history/<机器人QQ>.sqlite`，当前账号对应 `data/aichat/history/87654321.sqlite`。首次收到可记录的事件时创建，并不是程序启动时立即生成。原消息钩子记录消息、相关通知/请求以及正常插件的消息动作；记录机制本身不主动向 QQ 发消息。事件和回复不再按原来的 1024/512 字节截短；已配置 AI 密钥和密钥设置命令内容会隐藏。这里保留的是 OneBot 事件/动作数据，图片等资源不会自动下载为离线附件，也不保存模型内部思考过程。

Windows 对目录和数据库设置私有 ACL，仅当前运行用户与 SYSTEM 可访问；记录写入或配置读取失败会停止 Agent 动作，避免悄悄漏记后继续执行。现有 `data/aichat/agent/<会话编号>.txt` 长期记忆文件仍保留，记忆与事件档案分开使用；过长记忆只截取近期内容进入提示，不截断原文件。既有聊天角色权限、群开关与 @ 规则继续适用。

后台现有三类配置备份不包含对话数据库或长期记忆文件。需要另行备份对话时先停止 ZeroBot，再复制 `data/aichat/history/` 整个目录（包括可能存在的 WAL/SHM 文件）和 `data/aichat/agent/`；恢复前也先停止服务。当前未新增网页记录查看、编辑或导出入口。档案会随使用增长，应按实际磁盘容量安排备份和整理。

## 人物设定

[默认人物设定](../../third_party/zbputils/chat/char.yaml) 已同时写入本机共享 AI 设置的 Agent 人物设定和性别字段。其他 AI 字段、密钥和启动 JSON 保持原值。

保留 19 岁虚拟女生、粉蓝单马尾和校园风形象，把设定自然融入语气。通常简短接话，认真问题可以展开；少用固定口头禅和表情，傲娇以轻微俏皮为主，不挖苦用户。不编造经历或记忆，区分群内不同用户，只根据最新意图行动，成功后不重复发送，完成后结束当前任务。

后续在后台修改 Agent 人物设定即可应用，并保留记录。磁盘档案完整保留不代表模型每次都能读取全部旧记录；超出请求容量的内容暂时不会提供给模型，当前也没有新增历史检索工具。
