# AI 角色权限与隔离验证

## 使用与权限

在已响应且相关插件已启用的会话中使用`/gpt 问题`；群内普通聊天/Agent按既有@和触发概率规则处理。群总结仅群主、管理员或机器人主人可使用，GPT与总结共用每会话30秒额度。机器人主人由启动配置`zero.super_users`判定；群主/管理员身份来自当前群消息，机器人自身的管理员身份不会提高发言者权限。

| 发言者 | Agent角色 | AI会话参数命令 | 全局AI设置与上下文重置 |
| --- | --- | --- | --- |
| 机器人主人 | owner | 当前群/私聊允许 | 允许；模型地址/密钥/人物等要求主人私聊 |
| 非主人群主 | admin | 当前群温度、概率、语音输出允许 | 不允许 |
| 非主人群管理员 | admin | 当前群温度、概率、语音输出允许 | 不允许 |
| 群普通成员 | user | 不允许 | 不允许 |
| 非主人私聊用户 | user | 不允许 | 不允许 |

响应AT与使用Agent模式的聊天开关仍仅主人可修改；群主和管理员不会因此拥有主人权限。后台密码登录采用独立后台权限，不由QQ角色授予。

## Agent动作

角色动作白名单沿用程序内权限表：普通成员可发送当前群消息、查询当前群信息及使用已有读消息/表情/记忆动作，不能执行群管理或@全体成员；群主和管理员可执行当前群白名单内管理动作，不能设置管理员、退出群或修改全局AI；机器人主人沿用原owner白名单。

非主人白名单中带群目标的动作，包括`get_group_info`，只能作用于当前群；不能利用私聊或另一个群调用。普通成员的@全体成员检查同时覆盖OneBot消息数组和CQ文字格式。经过群目标校验的编号必须为正整数。动作即使在模型提示中出现，也必须通过程序权限与参数检查才执行。机器人自身权限和QQ平台限制仍可能令合法请求失败。

非主人私聊保留原规则：GPT可用；Agent的user白名单不包含`send_private_msg`，不会为本轮测试增开私聊动作，普通聊天回退仍受原配置影响。主人私聊已有真实文字验收。

角色代码升级并重启ZeroBot后对后续请求生效，无需修改日常插件/角色/密钥。隔离测试覆盖角色选择、白名单、当前群隔离、两种@消息格式与命令拒绝后的实际状态。真实验收可使用另一个非主人账号，也可按下述方法临时移除现有账号的主人资格；仅修改QQ群头衔不会移除`zero.super_users`中的主人资格。真实Agent动作不能用模拟结果替代，不在真实群演练禁言、踢人或退群。

## 使用现有账号验证真实角色

主人资格由启动配置决定，临时移除后需重启ZeroBot才能对后续消息生效，并影响该账号的所有会话。操作前备份原配置、记录控制库一致快照和原群身份；准备独立于QQ权限的本机恢复途径及有明确期限的自动恢复。不能让主人列表为空，本轮用机器人自己的QQ87654321作临时保留项，没有授予其他真人主人权限。测试结束立即恢复原配置并重启ZeroBot；自动恢复是兜底，不能代替结束后的身份、程序、配置和QQ在线核对。

在已响应且AI插件启用的测试群，普通成员发送`/gpt 请只回复‘普通成员测试成功’`，随后不加@发送`设置AI聊天温度51`：文字问答可用，温度不得改变。非主人私聊发送专用`/gpt`测试，再发送`查看AI聊天配置`：不得返回真实配置。无权执行的配置命令可能进入普通聊天并收到AI回复，应核对实际配置及回复内容，不能将“有回复”直接当作配置权限泄露。

管理员测试由群主临时授予该账号管理员，机器人主人资格仍保持移除。发送前核对新鲜成员信息和消息上报使用的缓存身份；用`get_group_member_list`的`no_cache=true`请求刷新，再读取缓存列表确认角色。本机NapCat v4.18.28的刷新可能异步完成，应等待并再次核对，单次新鲜`get_group_member_info`查询不能证明消息缓存也已更新。捕获专用测试消息的实时`sender.role`，不根据事后历史查询倒推当时角色。

当前群原温度位为0时，不加@发送`设置AI聊天温度0`应回复“成功”，0沿用默认温度0.7，因此这次验证不改原参数。随后发送`设置AI聊天不使用Agent模式`，非主人管理员不得修改此主人专属开关。其他群的原参数可能不同，测试前必须确定基线及恢复方式，不能直接照抄0作为通用不改数据的操作。结束后移除临时管理员并刷新、核对普通成员缓存，再恢复原主人配置。

机器人在群内为群主，只说明它可执行授权的角色切换，不代表真人发言者是群主。验证真人群主时应选择测试账号本来就是群主的授权群，再临时移除该账号的机器人主人资格；不需要为此转让群所有权。上面的账号和群号仅为示例。
