# 观察报告的进程关联

登录本机后台，在“运行概览”按[模型观察报告](model-observation-report.md)记录起点并下载。新程序在Windows启动后台时读取自身PID、操作系统记录的进程创建时间及当前程序SHA-256，仅计算一次；成功后前后统计快照都包含相同的 `process` 信息，新下载文件使用版本2。没有程序路径、账号、聊天内容、模型地址或密钥。

进程信息不新增请求、不修改配置；程序更新后重启ZeroBot生效，NapCat无需重启。统计计数及累计耗时口径保持。记录起点后，PID、精确启动时间或程序摘要变化会使原起点失效，即使统计起点时间碰巧相同，也不能混用前后资料。报告仍只保存在下载文件，页面起点在退出或刷新后清除。

使用[离线核对工具](observation-evidence-check.md)将版本2报告与资源观察目录核对：

```powershell
node scripts/check-observation-evidence.mjs --resource .local/live-observation/本次目录 --model 本次模型报告.json --output .local/本次关联核对.json
```

工具核对前后快照的三项身份信息一致，并与资源目录的PID、启动时间、程序摘要逐项匹配。时间支持明确偏移，按UTC纳秒规范化后比较；不会用近似几秒或仅PID相同代替精确启动时间。资源记录必须保持进程身份和程序不变，才可得到 `sameProcessVerified=true`。资源短窗口、阈值或日志检查不通过时仍可说明身份匹配，但 `compatible=false`；真实业务验收字段始终为false。

旧版本1报告继续按原格式核对次数、资源和时间范围，明确标记缺少进程身份，不能取得同进程证明。若新程序无法读取自身创建时间或程序摘要，概览仍提供统计，导出退回无身份的版本1，并在记录起点的说明中提示；不伪造创建时间、不把后台启动时刻当成操作系统进程启动时刻。非Windows平台暂不提供该关联信息，统计与旧格式仍可使用。

输出的“验证”表示这些文件的身份字段吻合，不是文件来源签名；自行修改资料可能产生自洽数据。模型HTTP完成不等于QQ回复成功，累计平均/最长耗时仍不代表窗口耗时或端到端延迟。不要因此关闭真实负载或其他真实角色待办。

实际Chrome5组流程、8种报告布局通过，桌面/手机截图已查看。下载初始零计数、3模拟请求增量及独立重启后零计数三份版本2文件，分别与Windows Get-Process记录和程序摘要核对；重启前PID109352/03:52:53.5609118Z，重启后PID105788/03:56:12.6128656Z，程序摘要相同。旧会话自动失效、重新登录后起点为空，随机凭据保持。独立实例`run-2829863660`两次启动/3模拟往返正常停止，自建页关闭，主题与视口恢复；证据`.local/model-identity-browser-result.json`、`-os-{first,second}.json`及`-downloads/`。浏览器操作初轮遇到视口能力尚未返回及重启后旧控件已消失，重新读取能力/页面状态后完成，没有用接口写入替代页面下载。

日常Chrome沿用浏览器正常填充登录，没有读取密码值；核对QQ87654321/108插件，下载第四份版本2报告，13.036秒窗口内新增0模型传输。11:59:29开始的60秒/3秒资源诊断记录21样本、60.0284574秒（`run-20261013-115929-e4ae7220`）；报告窗口完整位于实际样本之间，三项身份逐一吻合，离线结果`evidenceValid=true`、`sameProcessVerified=true`。由于`fullTiming=false`，资源检查/`compatible`仍为false，CLI退出2，业务验收始终false。这是短时身份关联验证，没有15分钟正式或真实负载验收；证据`.local/model-identity-resource-model-check.json`及`-daily-browser.json`。
