# 真实浏览器持续性能核对

当前程序的四组后台开关/接口轮询对照沿用[系统性能口径](system-acceptance-2026-10-02.md)，每组预热60秒、采样300秒。浏览器补充使用独立测试页，先在“运行日志”暂停更新取得静态显示，再在持续更新状态采样；每组同样预热60秒、采样300秒。测试控制器按5秒间隔发送模拟“翻转 abc”并校验回复，按2秒间隔读取其自有程序的Windows资源指标。

Chrome只读取受控测试标签页的CDP性能指标和页面已显示的统计。记录JS堆、主线程任务时间、布局/样式耗时、DOM/监听器数量与实际日志行数；不读取其他页面内容或浏览器账户数据。主线程任务时间占比与Windows机器人CPU口径不同，分别报告，不能合并称为整机或整个Chrome的CPU占用；共享渲染进程和测试工具采集可能影响该指标。

浏览器正式样本窗口中，以首个样本为基线核对JS堆最大增长不超过64MiB、主线程任务时间占比不超过20%、页面日志不超过1000行、无页面错误；至少30个样本、实际首末跨度不小于300秒，且窗口位于控制器正式资源窗口内。约每5秒采集，记录最大采样间隔、页面可见性和模式，持续组还要证实日志增加。阈值是本轮检查口径，不是响应时间或长期无泄漏保证；采样间的瞬时尖峰可能未被捕获。隐藏/切页时不把暂停轮询的样本当成持续前台更新；样本不足或提前结束不能标正式通过。

测试入口：

```powershell
Set-Location <项目目录>
$env:CGO_ENABLED='0'
go run scripts/start-admin-browser-performance.go -binary-name zerobot.exe -profile paused
# 完成暂停组后另起一组；保持页面自动更新：
go run scripts/start-admin-browser-performance.go -binary-name zerobot.exe -profile updating
```

启动后输出本次URL、登录文件和产物目录；Chrome使用该随机密码登录独立后台，打开日志并选择本组暂停/持续更新状态。终端输入`start`才开始该组预热和采样；期间可以读取进度文件，不能修改真实配置。控制器默认预热60秒、程序资源采样360秒，为Chrome独立300秒窗口保留协调余量；双方实际窗口分别记录，不称为相同采样窗口。`status`查看阶段，`stop`提前结束并停止本次程序；正式测量完成后也会自动停止。重复测量使用新的独立目录。

Chrome使用连接的Browser运行时完成登录/进入日志/暂停或保持更新；通过该标签页的CDP `Performance.enable` / `Performance.getMetrics`读取指标，页面只读检查当前日志行数、状态及可见性。预热后保存每个原始样本和最终截图，结束时关闭性能采集并关闭自建测试标签页。长窗口分批调用时保存进度，不因工具调用超时丢弃已完成的独立采集，也不单凭超时前提示判通过；最终读取实际首末时间、样本量和控制器退出结果。

完整资源样本、模拟消息结果、Chrome指标和页面截图保留在`.local/browser-performance/`，不进入Git。控制器只核对程序和模拟负载，`browserRendererMeasured=false`；Chrome结果另存，不能因控制器单独通过就关闭整个性能待办。
