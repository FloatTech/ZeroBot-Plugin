## 使用方法

刷新并重新登录 [本机后台](http://127.0.0.1:3010/)，进入“备份恢复”。可查看最近备份、选择范围手动创建、预览已有备份，再勾选覆盖确认并恢复。取消预览不改变配置；预览本身只读取目标和当前状态。

一次操作一个范围，各范围分别恢复，不提供跨文件的一键整机回滚：

| 范围 | 包含内容 | 生效方式 |
| --- | --- | --- |
| 启动配置 | 完整启动 JSON：所有 OneBot 连接、Token、主人、其他字段 | 保存文件后需重启；当前驱动与启动快照保留 |
| 控制数据库 | 整个控制库：开关、默认翻转、继承、群参数、AI 扩展、响应、封禁及库内插件数据 | 控制层提交后立即更新；其他插件的业务缓存可能需要重启，页面统一提示重启 |
| 后台启用与地址 | `.local/admin/options.json` 中 enabled/address | 托管宿主下次启动读取；恢复后可能关闭后台或改变访问端口 |

后台密码、会话、设置码、NapCat/QQ 登录、聊天媒体、素材和其他业务数据库不在恢复范围内。后台设置文件缺失或不符合回环地址格式时，不提供对应手动备份选项。通过命令行直接启动时，后台选项文件不会覆盖已经给出的启动参数。

控制库恢复覆盖所有库内数据，可能同时回退部分插件在该库保存的计数；不要把它理解成只恢复某一个插件的开关。恢复不会自动发送 QQ 消息，也不会自动重启进程。正在执行的 AI 请求仍可能继续使用它之前取得的配置快照；真实模型测试继续保留为 [TODO-AI-01](todo.md)。

## 保护与恢复机制

备份放在受限的本机目录，不提供明文配置读接口、下载接口或任意路径访问。列表只返回 ID、时间、格式版本、范围、大小和摘要是否存在；预览只返回覆盖说明、是否变化及表/记录数量，不返回凭据或原始数据库行。

新 JSON 备份包含实际存储 JSON 内容的 SHA-256；保留未知字段、大整数及原字段语义，校验覆盖 HTML 和 Unicode 转义后的内容。已有控制库快照继续校验 manifest 的版本、固定文件名及摘要；预览时额外执行 SQLite quick_check，并要求源库和当前库结构一致。旧版无摘要 JSON 备份仍可读取，预览明确提醒不能证明它未被修改。摘要用于发现损坏，不是数字签名；本机目录仍需保持私有。

只接受本程序生成的备份 ID，拒绝绝对路径、目录穿越、链接文件及链接祖先目录。单份启动配置限 1 MiB、控制库限 32 MiB；数据库解析限制 512 个 schema 项、10 万条记录和约 64 MiB 数据内存预算。列表最多展示最近 200 个备份，目录超过 4096 项时提示先在本机整理；不自动删除旧备份。

恢复请求必须带已登录会话、CSRF、明确确认，以及与该会话、目标内容和当前状态绑定的十分钟预览凭据。进程重启、预览过期、退出登录、目标被修改或当前状态改变后，旧凭据不能继续恢复。无变化时不创建多余备份、不写文件。

有变化时先保存当前状态，备份失败则拒绝覆盖。JSON 通过同目录私有临时文件、同步和替换写入；替换前再次检查外部编辑，失败保留原文件。控制库在与普通控制写入共用的 Manager 锁下，用一个 SQLite 事务复制匹配表的数据；不执行备份内存储的 SQL。写事务内再次比较当前版本，中途失败全部回滚。提交后才更新默认翻转及失效开关、响应、黑名单和封禁缓存。恢复前的备份可以再次预览恢复，以撤销上次成功恢复。

恢复演练还发现并修复原封禁实现中 uint64 查询与 int64 存储不一致的问题；缓存未命中时也必须继续检查全局封禁。封禁/黑名单的读取与缓存写回现在持有同一锁，避免恢复后旧读者重新放回过期结果。相关写入仅在成功提交后改缓存，不增加恢复以外的业务操作。

本记录首轮交付时，自动写前备份覆盖网页/聊天的插件开关、默认翻转、AI 扩展、AI 群参数和启动 JSON。后续已补齐响应/沉默、封禁/解封及插件禁止/允许，详见 [控制策略备份记录](control-policy-backups-2026-10-02.md)。业务计数及外部文件修改不逐次备份；可手动备份整个控制库。
