# 模型请求观察报告

登录本机后台，进入“运行概览”的“模型请求观察报告”。这项功能使用已有模型接口统计，不新增模型请求，不修改机器人配置。

1. 等待概览成功读取后，点击“记录观察起点”。记录的是最近成功读取的统计快照，时间以报告里的`before.checkedAt`为准，不是点击瞬间。
2. 正常使用机器人，保持这个页面打开；概览每10秒读取一次。也可点击“刷新状态”取得新的结束快照。
3. 点击“下载观察报告”，保存JSON文件。报告含前后累计快照和总计/四类请求次数变化，不含账号、聊天内容、地址、模型名称、密钥或配置。
4. “重新记录观察起点”立即替换本页起点；“清除观察起点”仅清除本页记录，机器人累计统计保持。

仅已登录、概览可见、成功读取且当前没有读取/下载操作时可以记录或下载。读取失败或统计无效时禁用下载，保留起点等待重新读取；切到其他后台页面或隐藏标签保留起点，但清除当前快照，回来后重新读取。刷新整个网页、退出或会话失效后起点清除；不会写入浏览器持久存储，不能自动恢复上次观察。机器人重启或前后时间/累计计数无法核对时原起点自动失效，需要重新记录。

文件名为`zerobot-model-observation-时间.json`。下载失败显示通用提示，等待按钮恢复后重试；临时下载链接自动清理。发起下载不代表已经保存文件，应以浏览器下载结果为准。按钮不要求确认框；修改本地观察起点不涉及后台保存。

## 报告口径

格式为`zerobot-model-observation`；Windows当前程序可读取[进程关联信息](model-observation-identity.md)时导出版本2，前后快照增加固定三项`process`字段。无关联信息时保留版本1，并在记录起点时提示。只导出固定字段，忽略接口的其他属性。时间保留UTC最多9位小数，窗口秒数按浏览器毫秒精度计算；即使间隔显示0秒也不认定观察有效或业务通过。

| 字段 | 含义 |
| --- | --- |
| `before` / `after` | 同一次进程统计起点的前后完整快照，固定四类及累计次数、平均/最长传输耗时 |
| `before.process` / `after.process` | 版本2：PID、操作系统创建时间、程序SHA-256；无路径或QQ账号，三项必须一致 |
| `window.started` | 两次读取之间新发起的HTTP传输数，重定向逐跳计数 |
| `window.completed` / `failed` / `incomplete` | 两次读取之间结束并归入接口完成、失败、提前关闭的数量 |
| `window.activeAtStart` / `activeAtEnd` | 起点和结束快照里仍进行中的请求数量 |
| `window.categories` | GPT／群总结、普通聊天、Agent、识图的同口径变化 |
| `window.durationSeconds` | 结束读取时间与起点读取时间的间隔，不是每条QQ回复耗时 |
| `scope.latencyScope` | 固定`process-cumulative`，平均/最长耗时属于各快照的本次启动累计值 |
| `scope.businessAcceptancePassed` | 固定`false`；报告不会自动宣布真实业务通过 |

窗口内结束的请求可能在起点之前已经发起。核对关系为“窗口新发起 + 起点进行中 = 窗口三类已结束 + 结束进行中”。开始次数和结束次数不要求相等，不能把窗口计数直接当成某一批QQ消息的成功率。报告不计算窗口平均或最长耗时；累计最长值不能通过两次快照相减得到窗口最长值。HTTP传输完成也不保证解析、Agent动作或QQ回复成功，完整口径见[模型请求统计](model-request-statistics.md)。

模型请求报告与[资源观察](live-performance-observation.md)是两个独立来源。资源采样脚本不读取本报告；维护者可用[离线核对](observation-evidence-check.md)检查已保存文件、UTC范围及版本2进程身份。版本1仍不能证明同进程，两种版本都不测量QQ端到端延迟。不要把其他进程、重启前后的快照或历史资源结果拼接成当前构建的真实持续负载验收。

## 独立自动化验收

开发环境可从仓库根目录运行`go run scripts/start-model-observation-acceptance.go -binary-name zerobot.exe -lifetime 20m`。需要本机维护工具、回环监听/运行临时程序权限；随机密码仅在本次目录`login.txt`内，临时地址由输出给出。所有配置、账号、模型都是独立模拟数据，不读取日常密码或接入真实QQ/模型。

命令`requests`每次只生成3条合成GPT往返，最多20批；每批新合成会话避开现有30秒限流。调用前核对原模拟OneBot地址与原本次模型地址，改成其他地址会拒绝；`status`读取统计，`restart`重启本次实例并核对随机凭据保持，`stop`停止本次实例。输入结束或限定时长到达也清理实例。本工具不修改Chrome下载设置，下载文件仍由正常浏览器按钮产生。

实际Chrome9组流程与8项布局指标通过：下载零请求、0→3、重新记录3→6三份实际文件并核对前后快照/窗口次数；切页保留、局部清除、网页刷新清除、重启会话与起点清除、退出。报告实际时间/内容以各文件为准，零值短窗口不计性能验收。四种宽度320/375/640/1280px×深浅，按钮及摘要无横向溢出；桌面与手机深色截图已查看（`.local/model-report-browser-{desktop,mobile}.png`）。

实际下载从Windows已知下载目录仅识别本次新增的报告文件，没有修改Chrome下载设置或读取其他下载。三份文件字节/来源/SHA-256及内容见`.local/model-report-browser-result.json`、副本`.local/model-report-downloads/`。独立实例`.local/model-observation-acceptance/run-1941381813`两次启动、两批6次模拟GPT、随机凭据保持和正常停止通过；自建页关闭，主题与视口恢复。报告文件无聊天、模型地址/名称/密钥、账号或配置，累计耗时未写入窗口平均/最长字段。

本轮未发送真实QQ消息或调用真实模型，没有重做15分钟资源观察；真实角色和持续业务负载仍按[待办](todo.md)验收，报告导出不会自动关闭它们。
